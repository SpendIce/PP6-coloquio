0. Repaso de la lección 4

¿Por qué un alias vencido responde 404 y no 410?

✘ Existe: es Gone, y significa «no vuelve».

✔ Y además, con una misma respuesta para desconocido y vencido (Q11), no se revela qué alias existieron.

✘ Spring devuelve cualquier código de estado.

1. La web C literal

La consigna pide «una página web con un campo dirección a acortar y un botón ACORTAR». Eso es static/index.html + app.js, servidos por el mismo Spring Boot Q15. Como la página y la API están en el mismo origen, no hace falta CORS.

  • El formulario tiene novalidate y el JS no filtra nada: la única validación es la del servidor. Así hay una sola regla, en el dominio, y la web muestra el message del 400. El test que lo cubre es laWebEntregaLaEntradaSinFiltrosPreviosDelCliente.
  • Muestra el enlace, el vencimiento (hora local), el aviso de reutilización y el QR descargable como PNG Q5 Q17.

2. El QR C

shortUrl (de la respuesta 201)
  → vendor/qrcode.js     biblioteca qrcode-generator (MIT): texto → matriz de módulos, corrección M
  → qr-code.js  QrPng    código propio: matriz → bytes PNG (sin canvas)
  → Blob → <img> y <a download="qr-<alias>.png">     los MISMOS bytes se ven y se descargan
  • Codifica el shortUrl, no el destino. Si codificara el destino, el QR saltearía al acortador: no vencería nunca, y el enlace corto no tendría sentido. La consecuencia aceptada es que un QR viejo sigue al alias reasignado (CONTEXT.md, «Código QR del enlace»).
  • Se genera en el navegador: el backend no guarda ni sirve imágenes, y solo devuelve el DTO.
  • Biblioteca vendorizada, sin CDN: la demo corre en una LAN que puede no tener Internet.
  • Encoder PNG propio (unas 190 líneas): arma el PNG a mano (firma, IHDR, IDAT con zlib sin compresión, CRC-32). Así funciona igual en el navegador y en los tests de Node. Tradeoff: es código propio que hay que mantener. Se compensa con un test que decodifica el PNG con bibliotecas independientes (UPNG + jsQR) y verifica que diga exactamente el shortUrl.

3. Las extensiones C «con solo tocarlo»

clic en el ícono → se abre popup.html → popup.js:
  tabs.query(activa)                 permiso activeTab: solo la pestaña, solo al tocar
  ¿no es http/https?  → TAB_NOT_SHORTENABLE (no llama a la API)
  storage.local "apiBase"            dirección del servicio (por defecto http://localhost:8080)
  LinkApi.createLink → POST /api/links       timeout de 10 s
  muestra enlace + vencimiento + aviso + QR  (mismo QrPng que la web)
  "Descargar QR" → downloads.download
  • Un solo código, dos paquetes: la fuente está en extensiones/compartido/, y sincronizar.sh la copia a chrome/ y firefox/, que solo agregan su manifest.json. Los tests verifican que las copias sean idénticas byte a byte. El QR también es el mismo archivo de la web.
  • Chrome MV3, Firefox MV2 T: en Firefox MV3 los permisos de host se conceden en ejecución y el pedido a la API puede quedar bloqueado en silencio en plena demo. En MV2 se conceden al instalar. En Chrome, MV2 ya no se admite. Instalación manual: en Firefox es «temporal» y se pierde al reiniciar el navegador.
  • Sin CORS en el backend: una extensión con host_permissions puede hacer fetch a otro origen sin que el servidor lo autorice. Además, el origen moz-extension://<uuid> es aleatorio por instalación, así que no se podría poner en una lista de CORS de forma limpia.
  • La dirección de la API es configurable porque la IP de la LAN cambia. Pero el shortUrl que se muestra siempre lo arma el servidor con PUBLIC_BASE_URL.

Ordená lo que pasa al tocar el ícono de la extensión:

  • Leer la URL de la pestaña activa
  • Comprobar que sea http o https
  • Leer la dirección de la API guardada
  • Hacer POST /api/links con la URL
  • Mostrar enlace, vencimiento, aviso y QR

✔ Eso es «con solo tocarlo genere y muestre», literal de la consigna. No hay un botón extra: abrir el popup ya acorta.

En voz alta: «¿Por qué el QR se genera en el navegador y codifica el enlace corto?»

Respuesta modelo

«Codifica el enlace corto para que el QR pase por el acortador: así respeta el vencimiento, y si el alias se reasigna lo sigue. Eso lo acordamos y lo avisamos. Se genera en el navegador porque el backend solo devuelve el contrato, y no tiene sentido guardar imágenes. La biblioteca está copiada en el proyecto porque la demo es en LAN, sin depender de un CDN. El PNG lo armamos nosotros para que los mismos bytes se vean y se descarguen, y se puedan testear en Node: un test lo decodifica con bibliotecas independientes y verifica que diga exactamente el shortUrl. La web y las dos extensiones usan el mismo archivo.»
